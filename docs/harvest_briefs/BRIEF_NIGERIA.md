## Method: mine, do not just search
Use WebSearch to find the portals, then QUERY them directly with WebFetch (build the URL yourself): repository search pages (DSpace /discover?query=, /simple-search?query=), OAI-PMH endpoints (…/oai/request?verb=ListRecords or GetRecord), OpenAlex API (https://api.openalex.org/works?search=...&per-page=50 and ?filter=), Crossref API (https://api.crossref.org/works?query=...&rows=50), CORE API pages, Semantic Scholar graph API, DOAJ, Europe PMC (https://www.ebi.ac.uk/europepmc/webservices/rest/search?query=...&format=json), PMC, Zenodo and Figshare search, Mendeley Data, Dryad, OSTI, SPE OnePetro open pages, ResearchGate and Academia public pages, Google Scholar-style query URLs, university repository listings by department (petroleum engineering, chemical engineering, geology) and by year, sitemaps and index pages, citation lists (cited-by and references of known Nigerian WAT papers). Page through result lists (page=2,3,...), do not stop at page 1. Follow every reference list for primary data. Try both common spellings (Escravos/Escravos, Bonny Light/Bonny-Light). Keep a list of the exact query URLs you ran in log.csv reason column or in a file queries.txt in your folder.
Rules unchanged: shell is blocked for most hosts, do not use proxies, Tor or mirrors. Paywalled and private data are out of scope. Unreachable PDFs go in log as unreachable with URL.
Extra: ANY Nigerian crude with pour point or wax content or API plus viscosity but NO WAT should NOT go in rows.csv. Instead put it in a second file bulk_only.csv (same columns, wat_c blank) so we can see pour-point and wax coverage. Cloud point rows follow the normal rule (tier C).
Stop after about 80 sources or three query rounds with nothing new. Final report under 200 words: sources examined, rows and oils added, bulk_only rows, best leads you could not open (URLs), and which query endpoints worked or were blocked.
